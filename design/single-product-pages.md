# One storefront / three product tabs
The source is dist/index.html. The homepage and /ruby-pearl/ are generated from this single source. Old /pearl/ and /ruby/ routes preserve their sharing metadata and redirect to the corresponding tab, keeping the campaign query. Tab selection updates hash/history, displayed panel, and default offer radio without unloading the document. There is one form and one canonical receipt destination /ruby-pearl/cam-on.html. The Apps Script endpoint, worksheet and payload contract have not changed. Preview mode still applies until the existing receiver v2 is deployed. No actual order was submitted. Existing tracking IDs are reused; tab views fire select_product_tab and view_item / Meta ViewContent, not duplicate PageView. Customer information remains blocked by the existing form and dialog markers; receipt has no tracking. Reference scent profiles are based on linked MFK pages and are explicitly not verified formula or longevity claims for the 50ml retail item. Do not add unverified reviews, stock or false countdowns. Run node scripts/sync-pages.mjs, node tests/single-product-tests.js, and existing frontend, receipt and tracking tests.
